## 1. `viewmodels/vehicles.js`
**`vehicleListView({ state, scope, now, role, personId, refs })`** returns:
- `scopes`: `[{ key, label, active }]` from `vehicleScopes(role)`. When `scope` is null, the default scope is active.
- `groups` by status in DESIGN order: 待派车, 已派车, 已完成, 已驳回, then withdrawn last.
  - Each group is `{ status, heading, items: [{ id, title (displayText reason), whenText (dayHeading + time), destination, applicantName, statusText, tone }] }`.
  - Empty groups are omitted.
- `empty`: `null`, or `{ kind: 'noData' | 'filtered', title, body, actionText | null }`. The copy is role-aware (review §4):
  - a fleet user with nothing to handle sees "暂无待派申请" / "No requests to dispatch"
  - a requester sees copy pointing at the request action, and `actionText` only if they can request
- `requestButton`: `{ text, disabled, reason }`.
- `badgeCount`: `vehicleBadgeCount(...)`.

**`vehicleDetailView({ state, id, now, role, personId, refs })`** returns:
- not found → `{ notFound: true, title, body }`
- `title`, `statusText`, `tone`
- `steps` (DESIGN 步骤条): `[{ key: 'submitted' | 'dispatched' | 'completed', label, state: 'done' | 'current' | 'todo', timeText | null }]`. `timeText` comes from the audit timestamps (review P1-5).
  - The "current" step is the step being waited on.
  - For rejected and withdrawn, `steps` is `null` and `rejectBanner: { text }` is shown instead (rejected only).
- `cells`: reason, destination, departure, passengers (`tn`), applicant, car (plate + model when set), driver, note.
- `actions`: from `availableActions(...)`, as `[{ key, label, kind: 'primary' | 'secondary' | 'danger' }]`. Dispatch is primary; reject, withdraw and cancelDispatch are danger.
- `warnings`:
  - the seat warning when a car is set
  - a pre-departure note when `complete` is available but `now` is before departure; the action stays listed, and the transition will refuse it
- No demo copy at all (review P1-1). The old "switch identity in Me" hint is gone.

**`dispatchSheetView({ state, id, now, refs, selectedCarId })`** returns:
- `title`
- `cars`: `[{ id, label (plate + model), seatsText, available, busyText | null, selected }]`, from `carAvailability` excluding this request
- `seatWarning` text or `null`
- `confirmText`, `cancelText`, `confirmDisabled` (no car selected, or the selected car is busy)

**`rejectSheetView()`**: `title`, `placeholder`, `confirmText`, `cancelText`. The reason is required, and its error text comes from `error.vehicle.reject.reasonRequired`.

**`vehicleFormLabels()` + `vehicleFormDefaults({ now })`** follow the same pattern as the meeting form. Passengers default to 1.

## 2. Schedule scope (additive; F3 is binding `scheduleView` right now, so keep the existing output keys unchanged)
`scheduleView` accepts the optional `scope`, `role` and `personId`.
- It adds `scopes: [{ key, label, active }]` from `scheduleScopes(role)`. When `scope` is null, the role's default is active.
- It applies `filterScheduleByScope` to `items` and to the `hasItems` dots.
- When `role` is absent, the behavior is exactly as today (`all`, and `scopes: []`).
