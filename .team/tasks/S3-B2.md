## 0. SDK transaction limits (design rule for this and later tasks)
In `wx-server-sdk`, a transaction supports only `tx.collection(name).doc(id).get/set/update/remove` and `tx.collection(name).add`. **No `where` queries inside a transaction.** So:
- Make the fake DB's transaction object enforce this: `tx.collection(name)` exposes only `doc()` and `add()`; calling `where`/`get`/`count`/`orderBy` on it throws `Error('where is not supported in transactions')`. Add a fake-db test.
- Design documents so every in-transaction lookup is by `_id`.

## 3. `admin` handler (sysAdmin only; every write audited)
`createHandler({ db, now, log, randomInt })` (default `randomInt` = `crypto.randomInt`).
- `issueInvite({ employeeId })` → `{ ok: true, code, expiresAt }`.
  - The employee must exist and be active (`admin.employeeNotFound`, `auth.employeeDisabled`). An employee who already has a binding → `admin.alreadyBound`.
  - Revoke that employee's open invites (query by `employeeId`, unused and unrevoked; set `revokedAt`) **before** the transaction. Then add the new invite.
  - Regenerate on the very unlikely hash collision (max 5 tries, then `server.error`).
  - The plain code appears only in the response, never in a document or the audit log. Audit `invite.issue`.
- `revokeInvite({ employeeId })` → revokes open invites; `{ ok: true, revoked: n }`. Audit `invite.revoke`.
- `disableEmployee({ employeeId })`:
  - Set `status: 'disabled'`, `disabledAt`, `updatedAt` and `rev + 1`.
  - Remove that employee's bindings (query by `employeeId`) and revoke their open invites.
  - A sysAdmin cannot disable themself (`admin.cannotDisableSelf`). Audit `employee.disable`.
- `setFlags({ employeeId, dispatcher?, sysAdmin? })`: booleans only (`admin.invalid`).
  - Refuse to remove the last active sysAdmin (`admin.lastSysAdmin`).
  - Audit `employee.flags` with the changed flags.
- `updateSupports({ secretaryId, leaderIds })`: allowed for **secretaryAdmin or sysAdmin** (§6), so check it before the sysAdmin gate.
  - The target must be an active `secretary` (`supports.notSecretary`).
  - `leaderIds` must be an array of distinct active `leader` ids, possibly empty (`supports.leaderInvalid`).
  - Upsert the `supports` doc (`_id` = secretaryId) with `updatedAt`, `updatedBy`, `v` and `rev`. Audit `supports.update` with the new `leaderIds`.

## 4. `auth.redeemInvite({ code })`
For unbound callers only. Already bound → `auth.alreadyBound`.

1. **Rate limit** (`rate_limits`, `_id` = openid): if 5 failed attempts fall within the hour-long window starting at `windowStart`, return `auth.tooManyAttempts` without checking the code. A window older than one hour resets.
2. **Normalize** the code. Invalid shape → a failed attempt plus `auth.inviteInvalid`.
3. **Transaction:**
   - Read the invite by hash: missing or revoked → `auth.inviteInvalid`; used → `auth.inviteInvalid`; expired → `auth.inviteExpired`.
   - Read the employee: active, else `auth.employeeDisabled`.
   - Read `bindings/<openid>`: if it exists → `auth.alreadyBound`.
   - Write the binding (`_id` = openid, `employeeId`, `inviteId`, `boundAt`) and mark the invite used (`usedAt`, `usedBy` = openid).
   - Audit `invite.redeem` (actorId = the employee id).
4. **Employee already bound elsewhere:** check with a `where({ employeeId })` query **before** the transaction (CloudBase's unique index on `employeeId` is the final guard). Bound → `auth.inviteInvalid`; don't reveal more.
5. **Failure accounting:** every failure in steps 2–4 except `auth.tooManyAttempts` and `auth.alreadyBound` increments the rate-limit count (outside the transaction). Success clears it.
6. **Result:** `{ ok: true }` plus the same payload as `whoami`.

## 5. Tests (new `tests/admin.test.js`, `tests/auth.test.js`, `tests/invite-code.test.js`; extend fake-db tests)
- **Codes:** alphabet has 32 characters with no `0 O 1 I`; `generateCode` is deterministic with a stub `randomInt`; `normalizeCode` handles case, spaces and dashes and rejects bad lengths and characters; `hashCode` is stable SHA-256 hex.
- **Issuing:** returns a code whose hash is the stored `_id`; the plain code is absent from `_dump()` (search every collection's JSON); re-issuing revokes the old invite; bound and disabled employees are refused; a non-sysAdmin gets `permission.denied`.
- **Redemption:**
  - The happy path creates the binding, marks the invite used, and `whoami` is then bound.
  - Covered failures: reuse, revoked, expired (use the injected `now`), wrong code, disabled employee, already bound, employee bound elsewhere.
  - After 5 failures, `tooManyAttempts` comes back even with a valid code; after the window passes, a valid code works.
  - A redeem whose transaction throws mid-way leaves no binding (rollback).
- **Admin:** disabling removes bindings and revokes invites, after which `whoami`/`directory` say `auth.employeeDisabled`; the self-disable and last-sysAdmin guards work; flag type checks; supports validation; a secretaryAdmin may update supports but not issue invites.
- **Audit:** every write action adds exactly one audit entry with the right `action`/`entity`/`entityId`, and no entry contains a plain code.
