## 1. Vehicle domain completion (review P1-5): `domain/vehicle.js`, `data/reference.js`
- **Derived car availability.** `carAvailability(cars, vehicles, { date, time, excludeVehicleId, windowMinutes = 120 })` returns `[{ carId, available, busyWith: vehicleId | null }]`.
  - A car is busy when another vehicle request with `status === 'assigned'` uses it on the same date with an overlapping window `[time, time + windowMinutes)`.
  - This replaces the old hard-coded `busy` flag.
- **Seat check.** `seatWarning(car, passengers)` returns `null` or `{ code: 'vehicle.seats.exceeded', seats, passengers }`. It is non-blocking. Add the key to both locales with `{seats}` and `{passengers}` params.
- **Completion guard.** `transition(... 'complete' ...)` returns `{ ok: false, code: 'vehicle.complete.beforeDeparture' }` when `now` is before the departure date and time. Add the key.
- **Dispatch onto a busy car.** `transition(... 'dispatch' | 'reassign' ...)` with a car that `carAvailability` says is busy returns `{ ok: false, code: 'vehicle.car.busy' }`. Add the key.
  - `transition` needs the other vehicles for this check: add `vehicles` to its options and default to `[]`.
- **Request validation.** `validateVehicle(input)` returns `[{ field, code }]` in form order, using the existing `vehicle.*` codes:
  - `reason` required, max 40
  - `destination` required, max 60
  - `date`, `time`
  - `passengers` an integer from 1 to 6
  - `note` optional, max 200

  Add `.tooLong` codes as needed, in both locales.
- **`createVehicleRequest(input, { id, applicantId, now })`** returns `status: 'pending'`, null ids and timestamps, `createdAt`, and trimmed strings.

## 2. Role-aware selectors (review P1-2): new `domain/roles.js`
- `roleHome(role)` returns `'vehicles'` for driver and `'schedule'` for everyone else.
- `vehicleBadgeCount(role, personId, vehicles)`:
  - driver: the number of `pending` requests
  - requester roles: 0 for now (a "my requests that changed" count needs read-tracking, so leave a TODO)
- `vehicleScopes(role)` returns `[{ key: 'all' | 'mine' | 'todo', default: bool }]`. The default is `todo` for driver and `mine` for others. `todo` is only for roles with `vehicle.dispatch`.
- `filterVehiclesByScope(vehicles, scope, { role, personId })`:
  - `mine` means `applicantId === personId`
  - `todo` means `pending` for a dispatcher, plus `assigned` where `driverId === personId`
- `scheduleScopes(role)` and `filterScheduleByScope`: `all` | `mine`, where `mine` means the person is an attendee or organizer (meetings) or the applicant or driver (vehicles). Leader defaults to `all`, others to `mine` (review P1-2: give the leader one real difference).
