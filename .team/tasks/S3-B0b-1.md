## 3. Visibility: new `domain/visibility.js`
Context `ctx = { supports, isLeader }`. Actor as above.
- `itemVisibleTo(actor, item, ctx)` per `DATA_MODEL.md` §4.2 for meeting items: a person in `leaderIds` (leaders only see items where they are in `leaderIds` **or** are organizer/attendee — never another leader's item otherwise); secretary: `leaderIds` ∩ supported ≠ ∅; secretaryAdmin: `leaderIds` non-empty; anyone: organizer or attendee. Cancelled items stay visible to the same people.
- `canEditItem(actor, item, ctx)`: organizer; a secretary supporting any leader on it; a secretaryAdmin for items with leaders; a leader in `leaderIds` for their own items.
- `vehicleVisibleTo(actor, vehicle, ctx)` per §4.3: with `forLeaderId`: that leader, secretaries supporting that leader, secretaryAdmins, dispatchers, the assigned driver, receptionists and receptionAdmins, plus the applicant. Without: the applicant, secretaries, secretaryAdmins, receptionists, receptionAdmins, dispatchers, drivers — **never leaders** (unless the leader is the applicant, which cannot happen because leader requests always set `forLeaderId`).
- `visibleItems(actor, items, ctx)`, `visibleVehicles(actor, vehicles, ctx)`.

## 4. Meetings as items: `domain/meeting.js` (keep the file and function names)
Meeting item shape (local store keeps instants as ISO strings): `{ id, kind: 'meeting', title, startAt, endAt, allDay: false, tz, location: '', roomId, attendeeIds, organizerId, category: 'regular', leaderIds, important: false, parentId: null, seriesId: null, notes, noteId: null, status: 'active' | 'cancelled', leaders: [{ leaderId, confirm, confirmedAt, declineReason: '', changedAt: null, changeNote: '', seenAt: null }], createdBy, createdAt, updatedAt, updatedBy, cancelledAt, cancelledBy, v: 1, rev: 0 }`. `agenda` → `notes`.
- `validateMeeting(input, refs)`: unchanged input (form strings `date`, `start`, `end` in the entry zone); add optional `category` (`regular | special`) and `important` (boolean) checks.
- `createMeeting(input, { id, actor, now, tz, isLeader, needsConfirm = true })`: `startAt`/`endAt` via `tz.fromZoned`; `leaderIds` = leaders among attendees + organizer; `leaders[]`: the actor's own entry `confirmed` if the actor is a leader, every other leader `needsConfirm ? 'pending' : 'none'`; `createdBy`/`organizerId` = actor.
- `meetingStatus(item, now)`, `canCancelMeeting(actor, item, now, ctx)` (= `canEditItem` and upcoming and not cancelled), `cancelMeeting(item, { actor, now, ctx, needsConfirm = false })` (leaders other than the actor get `pending` or `none` + `changedAt`; existing error codes), `findConflicts(candidateItem, items, refs)` on instants with `tz.overlaps` (meeting items only, skip cancelled and itself), `sortMeetings` by `startAt`, `filterMeetings`.

## 5. Vehicles: `domain/vehicle.js`, `domain/roles.js`
- Requests: `date` + `time` → `departAt` (ISO) + `tz`; new `forLeaderId`, `itemId: null`. `validateVehicle` input unchanged (form strings). `createVehicleRequest(input, { id, actor, now, tz, forLeaderId })`: leaders always get `forLeaderId = actor.personId`; a secretary may pass a supported leader; drivers cannot request (`permission.denied`).
- `carAvailability(cars, vehicles, { departAt, excludeVehicleId, windowMinutes = 120 })` on instants.
- `availableActions(vehicle, actor)` and `transition(vehicle, action, payload, { actor, now, cars, vehicles, drivers, windowMinutes })`: dispatch/reassign/reject/cancelDispatch need the `dispatcher` flag; dispatch/reassign take `payload.driverId` (must be in `drivers`; when absent and exactly one driver exists, use it; else `vehicle.driver.required`, new key in both locales); complete only by the assigned driver; withdraw only by the applicant. Timestamps become ISO instants. `complete` before `departAt` → existing code.
- `roles.js`: `roleHome(role)` unchanged; `vehicleScopes(actor)`: `todo` for dispatchers (pending) and drivers (assigned to them), default `todo` for both; `mine` default otherwise. `filterVehiclesByScope(vehicles, scope, { actor })`. `vehicleBadgeCount(actor, vehicles)`: dispatcher → pending count; driver → assigned-to-me count; else 0. `scheduleScopes(actor)` and `filterScheduleByScope(items, scope, { actor })` keep `all | mine` (`mine`: organizer, attendee, in `leaderIds`, applicant, assigned driver, or `forLeaderId`). **All lists filter by visibility first**, scopes second.

## 6. Schedule: `domain/schedule.js`
`scheduleItems(day, sources, now, viewerTz)`: an item belongs to every day `tz.spanDays(startAt, endAt, viewerTz)` touches; vehicles by `tz.dayKey(departAt, viewerTz)`. Items carry `startAt` for sorting. `datesWithItems(sources, days, now, viewerTz)`.
