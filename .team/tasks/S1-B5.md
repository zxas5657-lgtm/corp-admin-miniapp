## 1. `miniprogram/store/adapter.js`
- `createWxAdapter(wx)` and `createMemoryAdapter(initial)`.
  - Both return `{ get(key), set(key, value), remove(key) }`.
  - `get` returns `{ ok: true, value } | { ok: false, code: 'storage.readFailed' }`.
  - `set` and `remove` return `{ ok: true } | { ok: false, code: 'storage.writeFailed' }`.
  - **They never throw.** `wx.setStorageSync` can throw (quota), so wrap it.
- The memory adapter takes a `failNext({ op, code })` test hook to simulate failures.

## 2. `miniprogram/store/schema.js`
- `SCHEMA_VERSION = 2`, `DATA_KEY = 'corp-admin-v2'`, `LOCALE_KEY = 'corp-admin-locale'`, `ROLE_KEY = 'corp-admin-role'`.
- `migrate(data)` returns `{ ok: true, data } | { ok: false, code: 'storage.readFailed' }`.
  - `version` is missing, or `data` is not an object → not ok.
  - `version === 2` → validate the shape: `meetings` and `vehicles` are arrays, and each record has an `id` and `date`. Drop malformed records rather than crashing; count them in `dropped`.
  - Lower versions run through a `MIGRATIONS` map `{ [fromVersion]: fn }`, applied step by step.
  - There is no v1 → v2 migration: v1 was the prototype's `localStorage` on the web, and the mini-program never had it. Keep the mechanism and test it with a fake `{1: fn}` map passed in.
  - A version above `SCHEMA_VERSION` → not ok. Never downgrade silently.

## 3. `miniprogram/store/index.js`: the single place pages read and write
- `createStore({ adapter, seed, clock })` returns:
  - `load()`:
    - Reads `DATA_KEY`. When there is no data, it uses `seed()` and saves it.
    - When migration fails, it keeps the seed in memory but **does not overwrite** the stored blob, and returns `{ ok: false, code }` so the page can show an error state with retry or reset.
    - On success it returns `{ ok: true, dropped }`.
  - `getState()` returns `{ meetings, vehicles }`, a deep copy so pages cannot mutate it.
  - `addMeeting(record)` / `updateMeeting(record)`: write-through. They persist first and update memory only on success. They return `{ ok } | { ok: false, code: 'storage.writeFailed' }` (review P1-7: never navigate to success when the write failed).
  - `updateVehicle(record)`: same pattern.
  - `resetDemo()`: replaces data with `seed()`. **It must not touch `LOCALE_KEY`**, and it resets the role to the default `admin`.
  - `getLocale()` / `setLocale(locale)`: persist under `LOCALE_KEY`. `getLocale` returns `null` when unset (the app then uses the system language).
  - `getRole()` / `setRole(role)`: persist under `ROLE_KEY`; default `admin`. Validate against `ROLE_CAPS` keys.
  - `ui`: the cross-tab handoff, in memory only.
    - `setPendingFocus({ date, meetingId })`
    - `takePendingFocus()` returns it once and then clears it (review P1-6: focus must not be sticky)
    - `setSelectedDate(date)` / `getSelectedDate()`; the default is today from the clock
  - `subscribe(fn)` returns an unsubscribe function. Fire it after every successful mutation and after `resetDemo`, so visible pages re-render.
- Also export a lazily created app-wide singleton: `getStore()` builds it with `createWxAdapter(wx)`, `data/seed`, and `domain/clock` on first call. Tests use `createStore` directly with the memory adapter.

## Tests
`tests/store.test.js` and `tests/schema.test.js`.
- First load seeds and persists.
- A second store over the same memory adapter reads back what the first saved.
- A write failure leaves memory unchanged and returns the code.
- A read failure, a corrupt blob or a future version → `load` is not ok and the stored blob is untouched.
- Malformed records are dropped and counted.
- `resetDemo` keeps the locale and resets the role.
- `takePendingFocus` returns its value once.
- `getState` returns copies.
- `subscribe` fires on mutation and not on a failed write.
- Migration steps run in order (with the injected fake map).
- Plus tests for the fixes in §0.
