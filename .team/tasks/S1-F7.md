# S1-F7: automated screenshot pass in both locales (owner: cursor-exec)

## Phase A: do now (no DevTools login needed)
Goal: once a human has signed in to WeChat DevTools, one command produces every screen and state in zh-CN and en.

1. Add `miniprogram-automator` (the official WeChat DevTools automation SDK) as a **devDependency** and run `npm install`.
   - The install is pre-approved for this project.
   - Commit-relevant files: `package.json`, `package-lock.json`. `node_modules/` is already in `.gitignore`.
   - Keep `npm test` working without DevTools.
2. Write `scripts/screens.js`, plus an npm script `"screens": "node scripts/screens.js"`.
   - Connect with `automator.launch({ cliPath, projectPath })`.
     - Default `cliPath` is `C:\Program Files (x86)\Tencent\微信web开发者工具\cli.bat`, overridable with the `WX_CLI` env var.
     - `projectPath` is the repo root.
   - Before each run, call `wx.clearStorageSync()` through `miniProgram.callWxMethod`, then `reLaunch`, so every run starts from seed data.
   - Iterate over **locales** (`zh-CN`, `en`) × the **scenarios** below. Set the locale with `miniProgram.evaluate`: require the i18n module and store, then call `changeLocale`. If evaluate cannot reach CommonJS modules, add a small `globalData.__dev` hook in `app.js` that is **only active when `config.DEV_ROLE_SWITCH` is true**.
   - Save each screenshot as `screenshots/<locale>/<NN>-<scenario>.png`. Add `screenshots/` to `.gitignore`; the screenshots are review artifacts, not source.
   - Also write `screenshots/index.html`: a simple two-column zh | en contact sheet, for the lead's review.
3. **Scenarios.** Each scenario is a page path plus a setup step. The role is set via `store.setRole`.
   1. schedule 10-24 (admin) and schedule 10-25 (empty)
   2. schedule after creating a meeting (banner + highlight)
   3. meetings list (admin), list filtered to empty, list as driver (disabled create + reason)
   4. meeting detail m3 (organizer can cancel), the cancel sheet open, m2 after cancel is refused (started), and a not-found id
   5. meeting form empty, the form after submitting empty (inline errors), the conflict sheet (a 5F Boardroom clash with m4), and the dirty-leave sheet
   6. vehicles as admin (mine), as driver (to-do + badge), and as reception
   7. vehicle detail v4 as driver: the dispatch sheet with a busy car disabled, the seat warning, and the reject sheet with an empty-reason error
   8. vehicle detail v3 (assigned): complete is refused before departure; v1 rejected (the reason banner)
   9. vehicle form with inline errors
   10. Me as admin, the language sheet, the reset sheet; the visitors and daily skeleton pages
   11. dev gallery with the pseudo-locale on (overflow check)
   12. the load-error state (corrupt the stored blob through `wx.setStorageSync('corp-admin-v2', { version: 99 })` and relaunch)
4. Make the script **fail soft**: one scenario failing logs and continues, and the exit code reflects the failures. Print a summary at the end.
5. Run `node --check scripts/screens.js`, `npm test` and `npm run check`. **Do not run `npm run screens`.** DevTools is not signed in yet, so the run waits for the owner.

## Phase B: later, after the human step
The human signs in to DevTools once with a QR code and enables Settings → Security → Service port. Then the lead runs `npm run screens` and reviews `screenshots/index.html`. Fixes become new tasks.

Constraints: don't edit `domain/`, `store/` or `viewmodels/`. The only allowed app-code change is the dev-only hook in `app.js`, if needed. Do not run git.
