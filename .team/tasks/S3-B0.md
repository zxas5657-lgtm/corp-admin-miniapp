# S3-B0: time-zone module (owner: codex-exec)

Read `DATA_MODEL.md` §2 (time model) first. The product now stores every time as an instant (UTC) plus the IANA zone it was entered in, and shows it in the viewer's local zone. This task builds the pure time-zone toolkit only. **Do not** change existing records, the store schema, `domain/clock.js`, meetings, vehicles, view models or pages: the switch of consumers and the store migration happen once, in S3-B0b, together with the move to `items`.

## 1. New `miniprogram/domain/tz.js`

Platform-free CommonJS, no dependencies. **Never use host-local Date getters/setters** (`getHours`, `getDate`, `setHours`, `getTimezoneOffset` …) except inside `deviceZone()`; work with `Date.UTC` and `getUTC*` so results do not depend on the machine's zone.

1. **Zone table `ZONES`** (fallback when `Intl` cannot do zones). Each entry: `{ id, city: { 'zh-CN', en }, std: minutes, dst: null | rule }`. Cover at least:
   - `UTC`; `Asia/Shanghai`, `Asia/Hong_Kong`, `Asia/Singapore` (+8); `Asia/Tokyo`, `Asia/Seoul` (+9); `Asia/Dubai` (+4); `Asia/Kolkata` (+5:30)
   - EU rule (last Sunday of March 01:00 UTC → last Sunday of October 01:00 UTC): `Europe/London` (0/+1), `Europe/Amsterdam`, `Europe/Berlin` (+1/+2)
   - US rule (second Sunday of March 02:00 local → first Sunday of November 02:00 local): `America/New_York` (−5/−4), `America/Chicago` (−6/−5), `America/Los_Angeles` (−8/−7)
   - AU rule (first Sunday of October 02:00 local std → first Sunday of April 03:00 local dst): `Australia/Sydney` (+10/+11)
   - `city` is the zone's own city in both languages, e.g. 上海 / Shanghai, 洛杉矶 / Los Angeles, 伦敦 / London.
2. **`isValidZone(tz)`**: true for table zones, or any zone `Intl` accepts when `Intl` zone support is present.
3. **`offsetMinutes(instant, tz)`**: minutes east of UTC at that instant. Use `Intl.DateTimeFormat(..., { timeZone, hourCycle: 'h23' }).formatToParts` when available; otherwise the table. Throw `RangeError` for an unknown zone.
4. **`toZoned(instant, tz)`** → `{ date: 'YYYY-MM-DD', time: 'HH:mm', weekday: 0–6 (Sunday 0), offset }`.
5. **`fromZoned(dateStr, timeStr, tz)`** → `Date`. Validate with the existing `isDateStr` / `isTimeStr` from `./dates` (return `null` if invalid). DST gap (a local time that does not exist): move forward by the gap (US 02:30 → 03:30). DST overlap (a local time that occurs twice): the earlier instant.
6. **`dayKey(instant, tz)`** = `toZoned(...).date`.
7. **`spanDays(startAt, endAt, tz)`** → the list of `YYYY-MM-DD` days the half-open range `[startAt, endAt)` touches in `tz`. An item ending exactly at local midnight does not include the next day. `endAt <= startAt` → just the start day.
8. **`overlaps(aStart, aEnd, bStart, bEnd)`**: half-open; touching edges do not overlap.
9. **`dualTime(instant, itemTz, viewerTz)`** → `null` when both zones have the same offset at that instant; otherwise `{ viewer: { date, time }, own: { date, time, dayShift: -1 | 0 | 1, city } }`, where `dayShift` is the own-zone date relative to the viewer-zone date and `city` is the table's `{ 'zh-CN', en }` (fall back to the zone id for both languages when not in the table). Data only; no strings or i18n.
10. **`season(instant, tz)`** → `'spring' | 'summer' | 'autumn' | 'winter'`, meteorological, northern hemisphere: Mar–May, Jun–Aug, Sep–Nov, Dec–Feb, by the local month in `tz`.
11. **`deviceZone()`**: `Intl...resolvedOptions().timeZone` when it is a valid zone; else pick the first table zone whose current offset equals `-new Date().getTimezoneOffset()`, preferring `Asia/Shanghai`, then the table order; else `'Asia/Shanghai'`.
12. **`probe()`** → `{ intl: boolean, intlZone: string | null, deviceZone, offsets: { [tzId]: minutes } }` for a later real-phone check (the WeChat runtime may lack zone data). Also export a test hook `_setIntl(enabled)` that forces the table path.

Export all of the above plus `ZONES`.

## 2. Tests: new `tests/tz.test.js`
- **Intl and table agree:** for every table zone, at instants every 6 hours across 2025-01-01 → 2030-12-31 (plus the exact transition instants), `offsetMinutes` with Intl equals the table path. Skip the Intl side for a zone only if Node's Intl rejects it.
- DST edges for US, EU and AU: the minute before and after each transition in 2026; `fromZoned` gap and overlap cases (2026-03-08 02:30 America/Los_Angeles; 2026-11-01 01:30 America/Los_Angeles; 2026-10-25 01:30 Europe/London).
- `toZoned`/`fromZoned` round trip for Shanghai and Los Angeles.
- `spanDays`: a 3-day trip; an item ending exactly at midnight; an item that crosses midnight only in the viewer's zone (e.g. 2026-10-26 22:00–23:30 Shanghai seen from Los Angeles).
- `overlaps` touching edges; `dualTime` same-offset → `null`, Shanghai vs Los Angeles with `dayShift` +1 and −1; `season` at month boundaries in two zones (an instant that is 30 Nov in LA and 1 Dec in Shanghai); invalid zones throw or return `null` as specified.
- A source check that `tz.js` uses no host-local getters/setters outside `deviceZone`.
- The suite passes regardless of the machine zone: run it once normally and once with `TZ=Asia/Shanghai` (PowerShell: `$env:TZ='Asia/Shanghai'; npm test`), and report both results.
