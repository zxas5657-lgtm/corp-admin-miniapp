# S1-B2: i18n runtime + locale skeleton (owner: codex-exec)

Context: PLAN.md §1.4 and CLAUDE_REVIEW.md §5.2–5.5. B1 is done, so `npm test` and `npm run check` already exist.
Target runtime: WeChat mini-program, plain JS, CommonJS (`module.exports`/`require`). No ES modules, no deps, no `wx` calls in this task.

## Files

1. **`miniprogram/i18n/index.js`** exports the following.
   - `LOCALES = ['zh-CN', 'en']` and `DEFAULT_LOCALE = 'zh-CN'`.
   - `normalizeLocale(lang)` maps any `zh*` (case-insensitive, `zh_CN`, `zh-Hans`, …) to `'zh-CN'` and everything else, including empty input, to `'en'`.
   - `getLocale()` and `setLocale(locale)`. `setLocale` normalizes, does nothing if the locale is unchanged, and notifies listeners.
   - `onChange(fn)` returns an unsubscribe function.
   - **`t(key, params)`**
     - Looks up a dotted key in the current locale and interpolates `{name}`.
     - A missing param leaves `{name}` visible.
     - A missing key falls back to zh-CN. If zh-CN also lacks it, it returns the key itself.
     - In dev mode it `console.warn`s once per missing key. Expose `setDevMode(bool)`.
     - Never returns undefined or an empty string for a missing key.
   - **`tn(key, n, params)`**
     - Uses `key_one` when n === 1 and the locale has it, otherwise `key_other`.
     - Passes `n` as a param automatically.
   - **`listJoin(items)`**
     - zh joins with `、`.
     - en: one item → `a`; two items → `a and b`; three or more → `a, b, and c`.
     - The `and` word comes from the locale file (`fmt.and`), not hard-coded.
   - **`localName(entity)`** returns `entity.name[locale]` with a fallback to `entity.name['zh-CN']`, or the string itself if `name` is a string.
   - **`displayText(v)`** returns `v` if it is a string, otherwise `v[locale]` with a zh-CN fallback, or `''` for null.
   - **`fmt.dayHeading(dateStr)`**: input `'YYYY-MM-DD'`.
     - zh: `10月26日 周一`
     - en: `Mon, Oct 26`
     - Build both from locale templates and arrays (`date.dayHeading`, `date.weekdayShort`, `date.monthShort`). Do not use `Intl`.
     - Compute the weekday from the date parts (`new Date(y, m-1, d)`), never from a UTC parse.
   - **`fmt.timeRange(start, end)`** returns `09:00–09:40` (en dash) in both locales.
   - **`firstDayOfWeek()`** returns 1 (Monday) for zh and 0 (Sunday) for en. Read it from the locale file (`date.firstDayOfWeek`).
   - **`dict(prefix)`** returns the nested object for a key prefix in the current locale, merged over zh-CN so no key is missing. Pages will `setData({ i18n: dict('meeting') })`.
   - Keep the state in module scope. No `wx`, no storage. Persisting the locale is store/'s job in B5.
2. **`miniprogram/i18n/zh-CN.js`** and **`miniprogram/i18n/en.js`**
   - Both have the same key set, which `npm run check` must pass.
   - Use the namespaces and wording from CLAUDE_REVIEW.md §5.2 and the glossary in §5.4.
   - At minimum:
     - `tab.*`, `nav.*` (schedule, meetings, vehicles, me, meetingNew, meetingDetail, vehicleNew, vehicleDetail, visitors, daily)
     - `role.<leader|admin|driver|reception>.label/hint`
     - `status.meeting.<upcoming|ongoing|done|cancelled>`, `status.vehicle.<pending|assigned|done|rejected>`, `status.unknown`
     - `error.*` (one key per domain error code; the starter list is below)
     - `state.*` (loading, submitting, genericErrorTitle, genericErrorBody, retry, reset)
     - `schedule.count` (plural), `meeting.attendeeCount` (plural), `vehicle.passengerCount` (plural)
     - `date.*` (dayHeading template, weekdayShort, monthShort, firstDayOfWeek)
     - `fmt.and`, `me.language` = `语言 / Language` in both files, `lang.zh` = `简体中文`, `lang.en` = `English` (identical in both files)
     - `demo.*` (placeholder; demo-only copy goes here)
   - Error code starter list (the domain will use exactly these, so keep the names):
     - `meeting.title.required`, `meeting.date.required`, `meeting.time.required`, `meeting.time.endBeforeStart`, `meeting.room.required`, `meeting.attendees.required`, `meeting.notFound`, `meeting.cancel.notAllowed`, `meeting.cancel.alreadyStarted`
     - `vehicle.reason.required`, `vehicle.destination.required`, `vehicle.date.required`, `vehicle.time.required`, `vehicle.passengers.range`, `vehicle.car.required`, `vehicle.reject.reasonRequired`, `vehicle.alreadyHandled`, `vehicle.notFound`
     - `permission.denied`, `storage.writeFailed`, `storage.readFailed`
   - Store error messages flat under `error` with the code as the literal property name, e.g. `error: { 'meeting.title.required': '…' }`. Make `t('error.meeting.title.required')` resolve this: when a dotted lookup fails, try the longest existing prefix whose remaining path is a literal key. Make check-i18n's `flattenKeys` and the parity check handle this consistently, and add a test.
