## F4a: `pages/meetings/index` (tab)
- Filter chips from `view.filters`: a horizontal scroll with 44px-tall hit areas (review P2), the active one in primary-soft.
- Date-grouped list: a `section-label` per `group.heading`, then cards. Each card shows:
  - title
  - `status-pill`
  - `timeText` · `roomName`
  - `organizerName`

  A cancelled meeting has a struck-through title and mute styling.
- Tapping a card opens `/pages/meeting-detail/index?id=…`.
- Empty states use `state-view` with `view.empty`. Its action (when `actionText` is present) opens the form.
- The bottom `primary-button` comes from `view.createButton`. When disabled, it shows `reason` underneath.

## F4b: `pages/meeting-detail/index` (sub-page; register it in `app.json`)
- `meetingDetailView` with the `id` from `onLoad` options.
- **Not found:** `state-view` empty with the view's copy, plus a back action.
- **Layout:**
  - title (20/600), with the status pill beside or under it
  - a `cell-row` group for `view.cells`; attendees use `stacked` when the text is long, or always in English if simpler
  - agenda as a stacked cell when present
- **"View in schedule":** call `store.ui.setSelectedDate(date)` and `store.ui.setPendingFocus({ date, meetingId })`, then `wx.switchTab` to the schedule. No banner.
- **Cancel (organizer only, `view.canCancel`):** a secondary destructive text button.
  - It opens a `bottom-sheet` (`danger`) with the `cancelSheet` copy.
  - Confirm calls `cancelMeeting`, then `store.updateMeeting`.
  - On success, toast (we stay on the page, per P2) and re-render, so the status becomes Cancelled and the cancel button disappears.
  - On a domain refusal, show `notice-bar` error with `t('error.' + code)`. On a storage failure, show the same with `storage.writeFailed`; the record is unchanged.

## F5: `pages/meeting-form/index` (sub-page; register it)
- Opened from the list button and from the list empty-state action.
- **Permission guard:** if `!can(role, 'meeting.create')` (role from `store.getRole()`), render `state-view` with `t('error.permission.denied')` and a back action instead of the form (DESIGN 无权限: "直接打开新建地址时给出说明").
- **Fields:** WeChat-style grouped `cell-row`s, built with `formOptions` / `formDefaults` / `labels`.
  - title: `input`, maxlength 40
  - date: `<picker mode="date">`
  - start and end: `<picker mode="time">`
  - room: `<picker>` over `rooms`
  - attendees: tappable chips over `people`, multi-select, each at least 44px tall
  - agenda: `textarea`, maxlength 500, optional, in a stacked cell
- **Submit:**
  1. `validateMeeting(input, refs)`. On errors, map them with `fieldErrors`: show each message inline under its field (`cell-row` `requiredError` + `errorText`), and scroll to `first` with `wx.pageScrollTo` and a selector. **No aggregated error bar** (review P1-7).
  2. `findConflicts(candidate, state.meetings, refs)`. If there are any, open a `bottom-sheet` with the `conflictWarnings` texts, plus "Submit anyway" and "Back" (non-blocking, P1-4).
  3. Submitting state: **keep the form mounted**, disable the inputs, show `primary-button` `loading` with `labels.submitting` and `top-progress` active. Keep a short delay (about 300ms) behind a `demo` flag only; don't fake latency otherwise.
  4. Then `createMeeting(input, { id: 'm' + Date.now().toString(36), organizerId: personId, now })` and `store.addMeeting(record)`.
     - **On failure:** leave the submitting state, keep every input, and show `notice-bar` error with `storage.writeFailed`. Never navigate.
     - **On success:** `store.ui.setSelectedDate(record.date)`, `store.ui.setPendingFocus({ date: record.date, meetingId: record.id, banner: true })`, then `wx.switchTab` to the schedule. The schedule (F3) shows the banner and the highlight.
- **Dirty-leave guard (P1-7):** if any field changed from the defaults, intercept back with the `labels.dirtyLeave` sheet.
  - Use the `page-container` component or the `onBackPress` / `wx.enableAlertBeforeUnload` approach, whichever is most reliable on current base libraries. Explain your choice in the reply.
- If the user leaves while submitting, the write must not complete half-way (DESIGN: "提交过程中如果返回上一页，这一次提交取消"). Check a `this._alive` flag before writing.
