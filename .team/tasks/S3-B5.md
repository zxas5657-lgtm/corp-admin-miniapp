## `viewmodels/week.js`: `leaderWeekView(config)`
Inputs: `{ state: { items, vehicles }, refs, date, mode: 'today' | 'week', filter, now, actor, viewerTz, ctx }`. `date` is any day in the week to show; the week starts on `i18n.firstDayOfWeek()` like the schedule week strip.

Output (plain data, already localized):
- `title`, `rangeLabel` (for example 「10月26日 – 11月1日」 / "Oct 26 – Nov 1"), `mode`, `todayDate`, `weekDates`.
- `overview`: up to 4 tiles `{ key, labelKey/label, count, active }` in this order when non-zero: pending confirmation, meetings, trips, visits. `filter` set to a tile key keeps only that kind (pending = items whose own leader entry is `confirm: 'pending'`).
- `days`: the 7 days in order, **today first when today is in the shown week** (then the following days, then the earlier days of the week; check DESIGN line 33 and make the order rule explicit in a comment). Each day `{ date, heading, isToday, empty, items }`. Consecutive empty days are merged into one row `{ empty: true, label: '周三 无安排' }` (or a range 「周三–周五 无安排」 when several in a row). `mode: 'today'` returns only today.
- Each item, from the same sources as `scheduleItems` (meetings and other items visible to the actor, plus the leader's own vehicle requests):
  - `id`, `kind`, `icon` (type key: meeting, trip, visit, milestone, vehicle), `timeLabel` (start–end in the viewer zone, 24 h; all-day → the all-day label), `title`, `place`.
  - `zoneLine`: only when the item's `tz` differs from `viewerTz`: the item-zone time with its short zone label, then the company home zone (`Asia/Shanghai`) when it differs from both the viewer and item zones, each with a relative-day word when the date differs from the row's date (次日 / 前一日, "next day" / "previous day"). Example for a leader in Los Angeles viewing a Beijing meeting: 「北京 次日 05:00」. Use `data/zones.js` labels.
  - `markers`: zero or more of `pending` (own leader entry `confirm: 'pending'`), `updated` (`updatedAt` later than the own entry's `seenAt`, and not created by the actor), `important` (`important === true`), `cancelled`. Routine statuses (upcoming, ongoing) produce no marker in this view.
  - `canConfirm` / `canDecline` (own entry pending and the item not cancelled; use the domain permission helpers), `expectedRev`.
  - `detail` for the expanded state: trips → departure, stops (place, client, time) and return, plus the meetings that fall inside the trip window; meetings → room, organizer, attendees; visits → visitor name, organisation, host; vehicle → destination, car and driver when assigned.
- Only the actor's own items for a leader (a leader never sees other leaders' items; visibility already enforces this; add a test).
