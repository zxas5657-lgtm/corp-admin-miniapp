- `index.js` (same shape in every function, ≤ 20 lines): `cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })`, `const db = cloud.database()`, then `exports.main = (event) => handler(event, { openid: cloud.getWXContext().OPENID, env: cloud.getWXContext().ENV })`. ## 3. Handlers in this task
Only these actions are real in B1; the rest are B2/B4. Every other handler exists with the router and returns `action.unknown` for everything.
- `auth`: `whoami` → `{ ok: true, bound: false }` or `{ ok: true, bound: true, employee: { id, name, title, role }, dispatcher, sysAdmin }`. Disabled → `auth.employeeDisabled`. (Invites are B2.)
- `directory`: `list` (bound callers only) → `{ ok: true, rooms, cars, employees }`; employees active only, fields `id, name, title, role` (no flags, no bindings).
- `prefs`: `get` → the caller's `reminder_prefs` doc or defaults (`DATA_MODEL.md` §5.11); `update(patch)` → only the §5.11 fields, `tz` must be a valid IANA name (use `domain/tz.js`; reject with `prefs.tzInvalid`), returns the saved prefs.
- `devSeed`: `run` → refuses with `seed.notDev` unless `context.env` is in `event.allowEnvs` **and** `event.confirm === 'seed-dev'`; otherwise clears and fills `rooms`, `cars`, `employees`, `supports`, `items`, `vehicle_requests`, `leader_notes` from `shared/data` (fictional only), converting reference people to `employees` docs (§5.1 shape) and `SUPPORTS` to `supports` docs. Never writes `bindings` or `invites`. Returns counts per collection. Note: the caller passes `allowEnvs` from the console test page, so no env id is committed.

## 4. Fake DB: `tests/support/fake-db.js`
In-memory stand-in for the subset of `wx-server-sdk` `db` the handlers use, so B2–B4 tests reuse it:
- `db.collection(name)`: `.doc(id).get() / .set({ data }) / .update({ data }) / .remove()`, `.add({ data })` (returns `{ _id }`), `.where(query)`, `.orderBy(field, 'asc'|'desc')`, `.skip(n)`, `.limit(n)`, `.get()` → `{ data: [...] }`, `.count()` → `{ total }`, `.where(q).update({ data })` / `.remove()` → `{ stats: { updated|removed } }`.
- `db.command`: `eq, neq, in, nin, gt, gte, lt, lte, and, or, inc, set, remove` with the real SDK's semantics for the cases above. `doc().get()` on a missing doc rejects like the SDK (an error with `errCode`), and the helpers handle that.
- `db.runTransaction(async (tx) => …)` with `tx.collection(...).doc(...).get/set/update/remove`; changes apply only when the callback resolves; a thrown error rolls back.
- `limit` defaults to 100 for server `get()`, like the SDK; document this.
- `createFakeDb(initial)` where `initial` is `{ collection: [docs] }`; `_dump()` for assertions. Deep-copy on read and write.
- Its own tests (`tests/fake-db.test.js`) for every operator and the rollback.
