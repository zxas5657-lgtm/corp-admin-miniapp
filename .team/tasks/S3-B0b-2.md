## 1. New kinds: new `domain/item.js`
Shapes per `DATA_MODEL.md` §5.8 (common fields as in meeting items). Kinds `travel`, `stop`, `visit`, `milestone`.
- `validateItem(kind, input, refs)` → `[{ field, code }]`:
  - all: `title` required, ≤ 40; times: `date` + `start` + `end` (end after start), or `allDay` + `date`; travel also allows `endDate` ≥ `date` (multi-day: start on `date` at `start`, end on `endDate` at `end`); `leaderIds` non-empty and all leaders (`refs.isLeader`); `notes` ≤ 500.
  - `stop`: `parentId` must be an existing `travel` item (`refs.itemById`), `stopType` in `depart | stop | return`, `location` required ≤ 60, `client` ≤ 60; times inside the parent's range.
  - `visit`: `visitorName` required ≤ 40, `org` ≤ 60, `headcount` integer 1–50, `purpose` ≤ 100, `visitorType` in `government | customer | internal | partner`, `receptionLevel` in `A | B | C`, `transport` in `selfDrive | pickup`, `plate` required ≤ 12 when `selfDrive`; exactly one leader (the host).
  - `milestone`: `allDay` allowed; `important` defaults to true.
  - Codes under `item.*` (e.g. `item.title.required`, `item.leaders.required`, `item.parent.invalid`, `item.stop.outsideTrip`, `visit.plateRequired`, `visit.headcount.range`); add every new code to both locales.
- `createItem(kind, input, { id, actor, now, tz, isLeader, itemById, needsConfirm = true })`: instants via `tz.fromZoned`; `stop` children copy `leaderIds` and `tz` from the parent; leaders[] rule as in `createMeeting`; `visit.plateClearAfter` = visit end + 30 days (ISO); for `pickup` leave `vehicleRequestId: null` (the link is made by the caller later).
- `itemStatus(item, now)` (upcoming / ongoing / done / cancelled) for every kind, all-day items ongoing for the whole local day in `item.tz`.

## 2. Weekly series
`expandWeekly(input, { until, max = 26 })` → array of inputs, one per week from `input.date` through `until` (inclusive, `YYYY-MM-DD`), same wall times. `createSeries(kind, input, options)` → items sharing a new `seriesId` (`options.seriesId`), ids `${options.id}-1…n`. Meetings use the same helper (`kind: 'meeting'` delegates to `createMeeting`).

## 3. Confirmation and changes: new `domain/confirm.js`
- `confirmItem(item, { actor, now })`, `declineItem(item, { actor, now, reason })` (reason required: `item.decline.reasonRequired`), `markSeen(item, { actor, now })` — only the actor's own `leaders[]` entry; `permission.denied` for non-leaders on the item.
- `changeItem(item, patch, { actor, now, ctx, needsConfirm, changeNote, expectedRev })`:
  - permission via `canEditItem`; `expectedRev !== item.rev` → `item.alreadyChanged`;
  - apply allowed fields only (title, times via `date`/`start`/`end`/`tz`, location, roomId, attendeeIds, notes, important, category, visit fields);
  - leader editing own item: their entry `confirmed` (also when it was pending); other leaders: `needsConfirm ? 'pending' : 'none'` with `changedAt` and `changeNote`;
  - a secretary/secretaryAdmin must pass `needsConfirm` as a boolean (`item.needsConfirm.required` otherwise);
  - bump `rev`, set `updatedAt`/`updatedBy`.
- Series: `applyToSeries(items, item, fn)` applies `fn` to `item` and every later occurrence (`startAt >=` item's) with the same `seriesId`; returns the changed items. Confirm/decline on one occurrence applies to the rest of the series this way.
- Every result is `{ ok: true, item }` / `{ ok: true, items }` or `{ ok: false, code }`.

## 4. Leader notes: new `domain/notes.js`
`createNote(text, { id, actor, now })` (leaders only; text required ≤ 200: `note.text.required`, `note.text.tooLong`); `convertNote(note, itemIds, { actor, now, ctx })` → `status: 'converted'`, `handledBy`, `handledAt`; `closeNote(note, { actor, now, ctx })`; `noteVisibleTo(actor, note, ctx)`: the leader, secretaries supporting them, secretary admins.

## 5. Visibility and permissions
- `permissions.js` caps: `item.create` (leader own, secretary, secretaryAdmin), `visit.create` (secretary, secretaryAdmin, receptionist, receptionAdmin), `note.create` (leader).
- `visibility.js`: receptionists and reception admins see every `visit` item; `canEditItem`: receptionist edits visits they created, receptionAdmin all visits. Trip children follow their parent's leaders (already via copied `leaderIds`).
- New `busySlots(actor, items, leaderId, day, viewerTz, ctx)` → `[{ startAt, endAt }]` with no titles, for reception roles (and anyone who can see the items); cancelled items excluded.
