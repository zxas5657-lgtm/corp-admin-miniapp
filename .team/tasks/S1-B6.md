# S1-B6: view models for schedule and meetings (owner: codex-exec)

**Why:** pages should be thin bindings. All derivation, formatting, grouping, localization and empty-state choice lives in pure, Node-tested functions. cursor-exec's pages call these and `setData` the result.

Context: CLAUDE_REVIEW.md §4 (state table), §5.2 rules 2–7, P1-4, P1-6, P1-7. DESIGN.md 关键页面 and 状态.

## Rules
- Files go in `miniprogram/viewmodels/`, as CommonJS.
- Use `i18n` (`t`, `tn`, `listJoin`, `localName`, `displayText`, `fmt.*`, `firstDayOfWeek`), `domain/*`, `data/reference` (injected through a `refs` param with a default) and `utils/status-tone` (the existing file by cursor-exec; require it, don't edit it).
- No `wx`, no storage. The inputs are plain data: `{ state, now, role, personId, ... }`. The output is plain JSON-able data for `setData` (no `Set`, no functions, no `Date`).
- Never concatenate sentences. Every visible string comes from `t()` with named params.
- **New copy keys:** add them to **both** locale files, grouped under the namespaces shown below. Write natural, short, internal-tool English, and Chinese matching DESIGN.md wording where it exists.
  - Demo-only phrases go under `demo.*` and must not appear in product copy (review P1-1).
- The CJK lint already covers `domain/` and `store/`. Add `miniprogram/viewmodels` and `miniprogram/utils` to its scan list in `scripts/check-i18n.js`.

## 1. `viewmodels/schedule.js`
`scheduleView({ state, date, now, focusId, refs })` returns:
- `date`, `todayDate`, `isToday`, `dayHeading` (`fmt.dayHeading`).
- **`week`**: the fixed week containing `date`, starting on `firstDayOfWeek()` (review P1-6: the strip does not re-centre).
  - `{ days: [{ date, weekday (short label), dayNum, isToday, isSelected, hasItems }], prevDate, nextDate }`
  - `prevDate` and `nextDate` are the same weekday −7 and +7 days.
  - `hasItems` comes from `datesWithItems`.
- **`items`**: `[{ kind, id, timeText, title, subtitle, statusText, tone, focused, url }]`
  - meeting:
    - time is `fmt.timeRange`
    - title is `displayText(title)`
    - subtitle is the room's `localName`
    - url is `/pages/meeting-detail/index?id=…`
  - vehicle:
    - time is `time` alone
    - title is `displayText(reason)`
    - subtitle is the car plate when assigned, otherwise `displayText(destination)`
    - url is `/pages/vehicle-detail/index?id=…`
  - `focused` is `id === focusId`.
- **`countText`**: `tn('schedule.count', n)`.
- **`empty`**: `null` when there are items, otherwise `{ title, body }`. Use the review §5.2 copy: "新建的会议和有效的用车申请会列在这里".
- **`backToToday`**: the label, or `null` when `isToday`.

## 2. `viewmodels/meetings.js`
**`meetingListView({ state, filter, now, role, refs })`** returns:
- `filters`: `[{ key, label, active }]` for `all | upcoming | ongoing | done | cancelled`. Cancelled is the last filter.
- `groups`: `[{ date, heading, items: [{ id, title, timeText, roomName, organizerName, statusText, tone, cancelled }] }]`, grouped by date in date order (review P1-6). The sort comes from `sortMeetings`.
- `empty`: `null`, or `{ kind: 'noData' | 'filtered', title, body, actionText | null }`.
  - `noData` means there are no meetings at all; `filtered` means the filter removed everything (review §4).
  - `actionText` (the new-meeting action) appears only if `can(role, 'meeting.create')`. It is null otherwise.
  - The copy must not tell drivers or front desk to create a meeting.
- `createButton`: `{ text, disabled, reason }`. `reason` is the DESIGN 主按钮 disabled explanation from `t()`, and it must not mention the demo role switch (that would be a `demo.*` key, and it is not used here).

**`meetingDetailView({ state, id, now, role, personId, refs })`** returns:
- `notFound: true` plus `{ title, body }` (product copy, no demo-reset wording) when `id` is unknown.
- Otherwise:
  - `title`, `statusText`, `tone`, `cancelled`
  - `cells: [{ key, label, value }]` for date (dayHeading), time, room, organizer, and attendees (`listJoin` of names; also `attendeeCountText` via `tn`)
  - `agenda` (or `null`)
  - `canCancel` (from `canCancelMeeting`)
  - `cancelSheet: { title, body, confirmText, cancelText }`
  - `viewInSchedule: { text, date, meetingId }`

## 3. `viewmodels/meeting-form.js`
- `formOptions({ refs })` returns `{ rooms: [{ id, label }], people: [{ id, label }] }` in the current locale.
- `formDefaults({ now, personId })` returns a fresh input object: date = today; start/end = the next full hour, +1h; attendees = `[personId]`; empty title and agenda.
- `fieldErrors(errors)` maps the `[{ field, code }]` from `validateMeeting` to `{ byField: { field: text }, first: fieldName | null }` via `t('error.' + code)`.
- `conflictWarnings(conflicts, { state, refs })` returns `[text]`.
  - room: `t('meeting.conflict.room', { room, time, title })`
  - attendee: `t('meeting.conflict.attendee', { person, time, title })`
  - Plus `{ title, submitAnywayText, backText }` for the confirm sheet (review P1-4).
- `labels()` returns every form label, the placeholders, the submit and submitting texts, and the dirty-leave confirm sheet texts.
